## 1. 現状理解（実行者への文脈共有）

「いま配信中か」をページ訪問時に判定してバッジを点灯する仕組み。ビルド時判定では間に合わないため、次の構成になっている:

```
トップページのバッジ（初期状態 hidden）      src/pages/index.astro:69-73（.ilive）
  └─ 訪問時に inline JS が fetch('/api/live')   index.astro:1036-1059
       ↓
Cloudflare Pages Function                    functions/api/live.ts（onRequestGet、25-46行）
  ├─ edge キャッシュ照会（キーはクエリを捨てて正規化）
  ├─ ミス時: resolveLiveStatus(fetchJson, env.YOUTUBE_API_KEY, チャンネルID)
  └─ レスポンスヘッダ cache-control: public, s-maxage=<ttl>, max-age=0
       ↓
判定ロジック                                  src/lib/live.ts
  ├─ loadLiveStatusWith（31-49行）: channels → playlistItems(50件) → 新しい順に
  │   上位 LIVE_CHECK_COUNT=10 件を videos.list で確認（計3ユニット/回・search.list不使用）
  └─ resolveLiveStatus（63-74行）: キー未設定→非ライブ+ttl 30秒 ／ 成功→ttl 120秒 ／
      例外→握りつぶして非ライブ+ttl 30秒（ページを壊さないフォールバック）
純パース                                      src/lib/youtube.ts の parseLiveStatus（177-195行）
```

設計意図（守るべきもの）: **s-maxage=120 でクォータ安全**・**失敗時は非ライブ+短TTLでページを壊さない**・**タイトルは textContent 挿入でXSS回避**・**max-age=0 でブラウザは毎回再検証**（消灯の持ち越し防止）。

### このセッションで扱う負債（要点）

1. **`src/components/LiveBadge.astro`（114行）は完全なデッドコード**。旧デザインのバッジで、黒×金リデザイン時に `index.astro` 内の `.ilive` 実装に置き換えられ、import 元がゼロになった。同じ `/api/live` クライアント処理が2重に存在している状態。
2. **`?live=1` のデバッグ配線が本番に残存**（`index.astro:1047-1051`）。誰でも `https://本番URL/?live=1` で偽の「配信中」バッジ＋固定文言を表示できる（textContent＋固定文字列なのでXSSではないが、スクショによる誤情報演出が可能）。リデザイン時の「昇格時にデッドコード掃除」の積み残し。
3. `resolveLiveStatus` の catch が無言（キー失効・クォータ枯渇が起きても**ログが一切残らず**「バッジが永久に点かない」障害に気づけない）。
4. TTL 値 120/30 が裸の直値で3箇所に散在。
5. `docs/setup/12-live-verification.md` が旧仕様（15分ビルド・ビルド時判定・LiveBadge.astro）のまま。

### 検証手段

- `npx vitest run tests/live.test.ts` — 8件（TTL 120/30、キー未設定、API呼び出し回数などを固定済み）。
- **`/api/live` をローカルで動かす唯一の方法**: `npm run build && npx wrangler@3 pages dev dist`（リポジトリ直下の `functions/` を自動検出。`http://localhost:8788/api/live`）。ただしフルビルドに本物の `YOUTUBE_API_KEY` が要るため、**このセッションの完了条件はすべて vitest ベース**にしてある。wrangler 確認は可能な環境でのみ任意実施。
- `astro dev` は Pages Functions を配信しないため `/api/live` は 404 →バッジは出ない（仕様どおりの挙動）。

### 絶対に壊してはいけない挙動

1. 失敗・キー未設定時に 500 を返さず「非ライブJSON＋ttl 30秒」を返す（テストで固定済み）。
2. 成功時 ttl 120秒・`max-age=0`。
3. search.list を使わない（クォータ）。呼び出し回数（成功時3回）を増やさない。
4. バッジのタイトル挿入は `textContent`（innerHTML にしない）。
5. `/api/live` のレスポンスJSON形 `{isLive, liveVideo: {url, title} | null}`（クライアントJSとの契約）。

### S6-02: 受け口 `/api/live`（onRequestGet）のテストを追加

- **どう変えるか**: `caches.default` を Map ベースのフェイクにして `globalThis` へ注入し、`onRequestGet` を直接呼ぶ:

  ```ts
  import { describe, it, expect, vi, beforeEach } from 'vitest';
  import { onRequestGet } from '../functions/api/live';

  function fakeCaches() {
    const store = new Map<string, Response>();
    return {
      default: {
        match: async (req: Request) => store.get(req.url)?.clone(),
        put: async (req: Request, res: Response) => void store.set(req.url, res.clone()),
      },
    };
  }

  function ctx(env: Record<string, string>, tasks: Promise<unknown>[]) {
    return {
      request: new Request('https://example.com/api/live'),
      env,
      waitUntil: (p: Promise<unknown>) => tasks.push(p),
    } as any;
  }

  beforeEach(() => {
    (globalThis as any).caches = fakeCaches();
  });

  it('キー未設定なら非ライブ＋s-maxage=30', async () => {
    const res = await onRequestGet(ctx({}, []));
    expect(res.headers.get('cache-control')).toContain('s-maxage=30');
    expect(await res.json()).toEqual({ isLive: false, liveVideo: null });
  });

  it('成功時は s-maxage=120 のJSONを返し、2回目はキャッシュから返す', async () => {
    // fetch をモックして「ライブ中」の3連応答を返す（tests/live.test.ts のモックを流用）
    // 1回目: fetchモックが3回呼ばれ、s-maxage=120
    // waitUntil のタスクを await してキャッシュ保存を完了させてから
    // 2回目: fetchモックの呼び出し回数が増えない（キャッシュヒット）
  });
  ```

  ※`functions/api/live.ts:14-46` を読み、`env` の型・キャッシュキーの正規化（クエリを捨てる）・`fetchJson` の import 経路（グローバル fetch を `vi.stubGlobal` でモックするのが最少手間）を実物に合わせる。フェイク `caches` は Cloudflare の `caches.default` 互換の最小実装で足りる。
- **完了条件**: `npx vitest run tests/api-live.test.ts` → 2件以上パス。`npm test` 全パス。
- **リスクと戻し方**: テストのみ。`globalThis.caches` の注入が他テストへ漏れないよう `beforeEach`/`afterEach` で張り替え・掃除する。
