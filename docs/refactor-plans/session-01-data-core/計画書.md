## 1. 現状理解（実行者への文脈共有）

このリポジトリは個人VTuber「和香松庵」の公式HP。Astro による**完全静的サイト**で、Cloudflare Pages にデプロイされる。「Googleカレンダーが予定の唯一の源泉」で、ビルドのたびに外部からデータを取り込んで再生成する。

このセッションの担当は**データの入口と純ロジック**：

- **純ロジック層（外部通信なし・テスト済み）**
  - `src/lib/ics.ts` — `.ics` テキスト → `StreamEvent[]`。RRULE展開・EXDATE除外・終日判定。
  - `src/lib/schedule.ts` — JST整形（`jstDateKey`/`jstTime` 等）・`upcomingEvents`・`groupByJstDay`。
  - `src/lib/weekly.ts` — `StreamEvent[]` → 週間ボード `WeekData`。**ポスター生成スクリプトが Node から直接 import する**ため、相対 import に `.ts` 拡張子が付いている（`weekly.ts:5-9` のコメント参照。外すと壊れる）。
  - `src/lib/youtube.ts` — YouTube API レスポンス → `Video`/`LiveStatus` 純パース。依存ゼロ（Cloudflare Workers からも安全に import できる）。
  - `src/lib/featured.ts` — `FEATURED_MARK = '#おすすめ'` の唯一の定義。**依存を足すこと厳禁**（Workers バンドルに波及するため。ファイル冒頭コメント参照）。
  - `src/lib/links.ts` — `externalAttrs(url)`（外部リンクにだけ `rel`/`target` を付ける）。
- **データ取得入口（ビルド時に実行）**
  - `src/lib/fetcher.ts` — fetch層。`fetchText`（15秒タイムアウト）と `fetchJson`（エラー文の `key=` 伏字）。
  - `src/lib/loadSchedule.ts` — ICS取得。失敗＝**例外＝ビルド失敗**（中途半端なデータで公開しない方針。`CLAUDE.md` §4）。
  - `src/lib/loadVideos.ts` — YouTube取得。中核（uploads）失敗＝ビルド失敗、副次（個別再生リスト・ライブ・PICK UP）は握りつぶして継続。
- **config**: `src/config/{site,profile,information,featured}.ts` — 表示文言・リンク・チャンネルID。
- **出力エンドポイント**: `src/pages/llms.txt.ts`（AI向け索引）、`src/pages/sitemap.xml.ts`（手書きパス配列）。
- **CI**: `.github/workflows/build.yml`（push＋毎時cron＋Discord `/更新` で build→deploy）、`keepalive.yml`（60日無コミットでscheduleが止まるGitHub仕様への対策）。

### 絶対に壊してはいけない挙動（このセッション関連分）

`refactor-instructions.md` の「Behaviors To Preserve」より：

1. 中核データ取得失敗＝ビルド失敗（`loadSchedule.ts` / `loadVideos.ts` uploads部）。
2. JST固定の日時計算（21:00 JST = 12:00 UTC 等。既存テストが固定している）。
3. 終日予定＝休業扱い、予定IDの一意性（冪等性の前提）。
4. lib層は外部入力を素通しし、エスケープは表示層（Astro既定）に委譲。**lib層で追加エスケープしない**。
5. `FEATURED_MARK = '#おすすめ'` の**値を変えない**（Discord連携・カレンダー既存データとの契約）。
6. `weekly.ts` の拡張子付き import を外さない（ポスターの Node 直接実行が壊れる）。
7. `build.yml` の `PAGES_PROJECT_NAME: wakamatsu-iori-hp`・`repository_dispatch types: [rebuild-site]`・concurrency 設定を変えない。

### 意図的な仕様（問題に見えるが触らないもの）

- `loadSchedule.ts` のキャッシュは PROD 時のみ、`loadVideos.ts` は常時 — **意図的な非対称**（各ファイルのコメントに理由あり）。
- `index.astro` はトップの動画取得だけ try/catch で握りつぶす — schedule 失敗＝ビルド失敗との**意図的な非対称**。
- `weekly.ts:14` の `export { FEATURED_MARK }` 再エクスポート — 過去リファクタの互換措置。

### S1-04: fetchText のエラーメッセージから秘密URLを伏せる

- **対象**: `src/lib/fetcher.ts:8-14`
- **問題**: `ICS_URL` は「URL自体が秘密」（Googleカレンダーの限定公開アドレス）なのに、HTTPエラー時のメッセージにURL全文が入る:

  ```ts
  throw new Error(`取得に失敗しました: HTTP ${res.status} (${url})`);
  ```

  GitHub Actions は Secrets を自動マスキングするため現状の実害は限定的だが、ローカル実行やログ転送で漏れうる（`CLAUDE.md` §3）。
- **どう変えるか**: URLの**オリジンだけ**を出す:

  ```ts
  export const fetchText: TextFetcher = async (url) => {
    const res = await fetch(url, { signal: AbortSignal.timeout(TIMEOUT_MS) });
    if (!res.ok) {
      // URL全文は出さない（ICS_URLはURL自体が秘密のため。CLAUDE.md §3）
    throw new Error(`取得に失敗しました: HTTP ${res.status} (${new URL(url).origin})`);
    }
    return res.text();
  };
  ```

  `tests/fetcher.test.ts`（S1-01で新設）に特性テストを1件追加:

  ```ts
  it('fetchText のHTTPエラーはURL全文を含まない（§3）', async () => {
    vi.stubGlobal('fetch', vi.fn(async () => new Response('ng', { status: 404 })));
    await expect(fetchText('https://calendar.google.com/secret/path.ics')).rejects.toThrow(
      /HTTP 404 \(https:\/\/calendar\.google\.com\)/,
    );
  });
  ```

- **完了条件**: `npx vitest run tests/fetcher.test.ts tests/loadSchedule.test.ts` → 全パス（loadSchedule のテストはエラー文言に依存していないため影響なし）。`npm test` パス数が1件増。
- **リスクと戻し方**: デバッグ時にURLのパス部分が見えなくなる（意図的なトレードオフ）。挙動が問題になったら `git revert`。
- **依存**: S1-01

### S1-06: keepalive.yml のシェル連結を明示的な if 文にする


  ※コミットメッセージ等の既存文字列は**現行ファイルの記載をそのまま**使う（上は形の例）。
- **完了条件**: ロジックの等価性をローカルで乾式確認:
