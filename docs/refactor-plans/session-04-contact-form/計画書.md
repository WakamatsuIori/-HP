## 1. 現状理解（実行者への文脈共有）

Googleフォーム埋め込みを撤去し、自作の問い合わせフォームに置き換えたばかり。送信フローは:

```
ブラウザ（src/components/ContactForm.astro）
  └─ fetch POST /contact/submit（FormData）
       ↓
Cloudflare Pages Function（functions/contact/submit.ts の onRequestPost、52-158行）
  1. Origin 同一チェック（56-60行）
  2. 入力取得（FormData/JSON 両対応、62-75行）
  3. ハニーポット＋入力検証 validateContact（85行。ハニーポット時は成功を偽装 87行）
  4. Turnstile 検証（TURNSTILE_SECRET_KEY があるときだけ。93-99行、実装 35-50行）
  5. Discord Webhook 通知（CONTACT_WEBHOOK_URL 設定時。108-127行）
  6. Google Sheets 追記（CONTACT_SHEET_ID＋SA 2変数が揃うとき。129-147行）
  7. 集約: 届け先ゼロ→503 / 全滅→502 / 1つでも成功→200（Promise.all 並行、150-155行）
```

- `functions/_lib/contact.ts`（96行・純ロジック）— `validateContact`（上限 `MAX = {name:100, email:200, subject:40, message:4000}`）・`sanitizeForDiscord`（@everyone無効化・```分断・切詰め）・`buildDiscordMessage`・`sheetSafe`（`= + - @` 先頭に `'` を前置＝数式インジェクション対策）・`buildSheetRow`。**テスト18件で固定済み**。
- `functions/_lib/google.ts` — サービスアカウントJWT。**session-03（カレンダー）と共用**。submit.ts は `getAccessToken`（scope=spreadsheets）と `appendSheetRow` を再利用しており、JWT実装の重複は無い。
- `src/components/ContactForm.astro`（198行）— トップ（`index.astro:363`）と `/work`（`work.astro:75`）の2箇所で共用。Turnstile ウィジェットは `PUBLIC_TURNSTILE_SITE_KEY` があるときだけ描画。**キー未設定でも送信可**（2026-07-01 の Turnstile 任意化以降）。
- `.github/workflows/sync-pages-secrets.yml` — GitHub Secrets → Cloudflare Pages シークレットの手動同期（workflow_dispatch のみ）。

### 環境変数の分岐（すべて「任意」だが組み合わせで挙動が変わる）

| 変数 | 効果 |
|---|---|
| `CONTACT_WEBHOOK_URL` | 無ければ Discord 通知スキップ |
| `CONTACT_SHEET_ID` + `GOOGLE_SA_EMAIL` + `GOOGLE_SA_PRIVATE_KEY` | **3つ揃って初めて** Sheets 追記 |
| `TURNSTILE_SECRET_KEY` | あるときだけ Turnstile 検証 |
| `PUBLIC_TURNSTILE_SITE_KEY` | ビルド時公開値。無ければウィジェット非表示のまま送信可 |
| Webhook も Sheets も両方未設定 | 503「フォームは設定準備中です」 |

### 絶対に壊してはいけない挙動

1. **ハニーポット時に成功を偽装して返す**（ボットに検知させない。`submit.ts:87`）。
2. **部分成功の容認**: Discord か Sheets のどちらか成功なら 200（設計コメント `submit.ts:105`）。
3. `sanitizeForDiscord`・`sheetSafe` による無害化（`CLAUDE.md` §3「外部入力は信頼しない」）。
4. `allowed_mentions: { parse: [] }`（Discord通知で@メンションを無効化。`submit.ts:115`）。
5. 選択肢 `CONTACT_SUBJECTS`（`contact.ts:8`）と `ContactForm.astro` の `<option>`（27-30行）の**手動同期**。片方だけ変えるとサーバー側400になる。
6. キー未設定でもビルドが通ること（`ContactForm.astro:11` の `?? ''` フォールバック）。

### 検証の制約

- `functions/` は型チェック対象外（session-03 の S3-10 完了後は `npm run check:functions` が使える）。
- Turnstile・Discord・Sheets の実疎通はローカル不可。**このセッションでは実送信を行わない**。マージ後にオーナーが本番フォームからテスト送信1件（Discord通知＋シート1行を目視、テスト行は削除可）で確認する。

### S4-05: Origin ヘッダの不正値で500にならないようにする

- **対象**: `functions/contact/submit.ts:56-60`
- **問題**:

  ```ts
  if (origin && new URL(origin).host !== host)
  ```

  sandboxed iframe 等は `Origin: null`（文字列）を送り、`new URL('null')` が **throw → Workers の未処理例外（500）** になる。防御コードが例外源になっている。
- **どう変えるか**: parse 失敗＝不正として 403 で返す:

  ```ts
  if (origin) {
    let originHost: string | null = null;
    try {
      originHost = new URL(origin).host;
    } catch {
      /* parse不能なOriginは不正扱い */
    }
    if (originHost !== host) {
      return json({ ok: false, message: '不正なリクエストです。' }, 403);
    }
  }
  ```

  ※既存の 403 返却の形（メッセージ文言・ステータス）は 56-60 行の現物をそのまま使う。**Origin ヘッダ無し（同一オリジンの通常送信で起こりうる）を拒否しない**こと（既存どおり素通し）。
- **完了条件**: `npm test` 全パス。可能なら簡易ユニットテスト（`onRequestPost` に `Origin: 'null'` のリクエストを渡すと 403 が返り、例外にならない）を追加。難しければ机上確認＋レビューで足りる（正常系の挙動は不変のため）。
- **リスクと戻し方**: 正常系（同一オリジン・Origin無し）は挙動不変。`git revert`。
- **依存**: S4-00

### S4-06: Turnstile 検証にタイムアウトと失敗ログを付ける

- **対象**: `functions/contact/submit.ts:35-50`（`verifyTurnstile`）
- **問題**: siteverify への fetch に**タイムアウトが無く**、Cloudflare 側の障害時に Workers の実行時間を食い潰しうる。また `catch { return false; }` が**無言**で、ネットワーク例外と「トークン不正」が区別できず障害調査ができない。
- **どう変えるか**（fail-closed の方針は**変えない**）:

  ```ts
  const res = await fetch('https://challenges.cloudflare.com/turnstile/v0/siteverify', {
    // …既存のオプションはそのまま…
    signal: AbortSignal.timeout(5000),
  });
  // catch 節に:
  } catch (e) {
    console.error('[contact] Turnstile検証でエラー（fail-closedで拒否）', e instanceof Error ? e.message : e);
    return false;
  }
  ```

- **完了条件**: `npm test` 全パス。`grep -n "AbortSignal.timeout" functions/contact/submit.ts` が1件。
- **リスクと戻し方**: 現在 `TURNSTILE_SECRET_KEY` 未設定運用ならこの経路は通らない。設定済みでも「5秒超は拒否」が新挙動になるだけ（従来は無限待ち）。`git revert`。
- **依存**: S4-00
