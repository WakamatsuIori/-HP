## 0. 共通部品（先に作ると B/C/D が速い）
### 0-1. Discord Webhook 送信ヘルパ
- 役割：与えた内容を Discord チャンネルに通知（フォーム受信・失敗通知・告知に共用）。
- I/O：`postDiscord(webhookUrl, { content?, embeds? })` → `fetch(webhookUrl,{method:'POST',headers:{'content-type':'application/json'},body:JSON.stringify(payload)})`。
- 環境変数：`DISCORD_WEBHOOK_FORM`（フォーム用）／`DISCORD_WEBHOOK_OPS`（監視・運用通知用）。用途で分けると見やすい（同一でも可）。
- 失敗時：Webhook自体の失敗はログのみ（ユーザー応答は別途）。

### 0-2. 確認プレビュー（ephemeral＋確定/やり直し）
- すでに `/予定` Step1 で実装済みのパターンを **そのまま流用**（KVに保留→`custom_id`にid→確定でコミット）。B3/B4 はこれを再利用。

### 0-3. スパム対策（フォーム用）
- **honeypot**（非表示フィールドが埋まっていたら破棄）＋ **Cloudflare Turnstile**（無料・サーバ側で `siteverify` 検証）。任意で KV による簡易レート制限。
- 環境変数：`TURNSTILE_SITEKEY`（公開・HTML）／`TURNSTILE_SECRET`（サーバ）。

## 1. A2 — 最新動画 自動取得（YouTube RSS・ビルド時）
- **目的**：動画セクションの手動更新ゼロ。鮮度の芯。
- **仕組み（ビルド時）**：
  1. `https://www.youtube.com/feeds/videos.xml?channel_id=${CHANNEL_ID}` を fetch（APIキー不要）。
  2. XMLから先頭 N 件を抽出：`yt:videoId` / `title` / `published` / サムネ=`https://i.ytimg.com/vi/<id>/mqdefault.jpg`。
  3. 取得成功→ `src/data/latest-videos.json` に書き出し（**スナップショットをコミット**）。表示は astro-embed `<YouTube id=…>`（ファサード／[動画05]）。
- **必要**：`CHANNEL_ID`（UC始まり24字）。更新は既存の毎時ビルド＋`/更新`に乗る。
- **フォールバック（[鮮度04]）**：fetch失敗時は**前回スナップショット(json)を使用**しビルドを止めない。表示に「最終確認：◯前」（取得日。公開日と別表記）。0件はセクション非表示or「準備中」。
- **テスト**：キー/ネット遮断で前回値継続（白画面なし）／0件で固定文言／公開日と取得日が混ざらない。
- **段階**：Step1＝最新1件ヒーロー。Step2＝グリッド数件（残りはリンクアウト）。

## 2. C2 お仕事依頼フォーム → Discord（＋ C1 お便りは同部品）
- **目的**：案件/お便りの受け取りを Discord に集約（DB/メール不要）。`work.astro` の空白を埋める。
- **フロント**：LPにフォーム。
  - C2 依頼：`お名前/活動名`・`連絡先`(メール or X等)・`依頼種別`(コラボ/案件/取材/その他 select)・`内容`(textarea必須)・`予算感`(任意)・`希望時期`(任意)＋Turnstileウィジェット＋honeypot。
  - C1 お便り：`お名前`(任意)・`本文`(必須)＋Turnstile＋honeypot。
  - 送信先：`POST /api/contact`（種別フラグ `kind=work|otayori`）。
- **エッジ関数 `functions/api/contact.ts`（Pages Function）**：
  1. honeypot空チェック→埋まってたら200で握りつぶし（黙って破棄）。
  2. Turnstile `siteverify`（`TURNSTILE_SECRET`＋token＋IP）→不合格は400。
  3. 入力バリデーション（必須/長さ上限/メール形式 緩め）。
  4. `postDiscord(DISCORD_WEBHOOK_FORM, { embeds:[{title:'お仕事依頼' or 'お便り', fields:[…], timestamp}] })`。
  5. 成功→`{ok:true}`返却→フロントで「送信ありがとう」。失敗→再送案内。
- **必要**：`DISCORD_WEBHOOK_FORM`・`TURNSTILE_SITEKEY/SECRET`。**保存しない**（Discordに流すだけ＝プライバシー良好。フォームに「内容はDiscordに通知されます」一言）。
- **a11y**：本物の`<label>`・必須表示・エラー文言・成功/失敗のaria-live。
- **テスト**：honeypot埋めで破棄／Turnstile無効で弾く／正常送信でDiscord着弾／長文・空必須でエラー。
- **付随**：`work.astro` に「お仕事の可否＋このフォーム」を設置（[制作工程03 案件獲得型]）。

## 3. D1 — 取得失敗 自動通知
- **目的**：API/動画/カレンダー取得が続けて失敗したら気づける（[鮮度04]の可観測性）。
- **仕組み**：
  - **ビルド時（A2/スケジュール等）**：fetch失敗で前回値フォールバックした時に `postDiscord(DISCORD_WEBHOOK_OPS, '⚠ YouTube RSS取得に失敗。前回値で継続（◯/◯ ◯:◯ JST）')`。
  - **エッジ（/api/live）**：連続失敗カウントが要る→**KVカウンタ**。N回連続(例3)で通知、成功でリセット（成功→失敗の遷移時のみ通知＝スパム防止）。
- **必要**：`DISCORD_WEBHOOK_OPS`（運用チャンネル・FORMと分けると見やすい）／KV（live用）。
- **スロットル**：毎ビルド通知しない（遷移時 or N回ごと）。
- **テスト**：擬似失敗で1通だけ届く／復旧でカウンタ戻る／通知が洪水にならない。

## 4. B3 `/お知らせ` ・ B4 `/ピックアップ`（Discordコマンド）
- **目的**：管理画面を開かず Discord で運営完結。
- **共通**：`/予定` の **確認プレビュー(確定/やり直し)＋KV保留** を流用（誤投稿防止）。確定で **データ更新→`repository_dispatch`(rebuild-site) 再ビルド**。データ書込は既存方式に合わせる（[HP自動化_計画] の Discord→R2→GitHub→Actions、または GitHub API で `src/config/*` を直コミット）。
- **B3 `/お知らせ`（INFORMATION）**：
  - options：`タイトル`(必須)・`本文`(必須)・`画像URL`(任意)・`重要度/期間`(任意)。
  - 保存先：`src/config/information.ts`（既存サンプル形式）に1件追記 or R2 json。確認プレビューに整形表示→確定で反映。
- **B4 `/ピックアップ`（PICK UP動画固定）**：
  - options：`動画URL`(必須・videoId抽出)・`ラベル`(任意＝おすすめ吹き出し)。
  - 保存先：`src/config/featured.ts`（現状=最新3本＋仮ラベル→特定動画固定の意向）。確定で差し替え→再ビルド。
- **必要**：既存Discord連携・権限チェック（オーナー専用）・データ書込手段・`repository_dispatch`。
- **テスト**：確定で反映＆再ビルド／やり直しで未保存／画像URL無しでも崩れない／既存表示が壊れない。

## 5. 環境変数まとめ（秘匿・コードに書かない）

## 6. 実装順・受け入れ条件（まとめ）
**波1**：① **共通部品0-1/0-3** → ② **A2 RSS**（鮮度の芯） → ③ **C2 依頼フォーム**（案件導線）。
**波2**：④ **C1 お便り**（C2の部品流用） → ⑤ **D1 失敗通知**（0-1流用＋KV）。
**波3**：⑥ **B3/B4**（`/予定`の確認プレビュー流用＋データ書込）。

各共通の受け入れ：秘匿情報は環境変数のみ／失敗で本文・サイトが壊れない（フォールバック）／reduced-motion等のa11y維持／通知がスパムにならない。

> 一度 0-1(Webhook送信)・0-2(確認プレビュー＝/予定で実装済)・0-3(Turnstile) を整えれば、C/D/B は組み合わせで素早く乗る。**鮮度(A2)＋受け取り(C2)を先に**、が事業効果が高い。
