# 外部サービス設定の手順書作成

CLAUDE.md §8「外部サービス側の手作業が必要になったら手順書を書いて案内し、完了を待つ」の具体化。

出典: `docs/setup/01-google-calendar.md` 〜 `12-live-verification.md` の既存12本で確立したフォーマット。

## 手順

1. **連番ファイルを作成する**: `docs/setup/NN-短い英語名.md`（NNは既存の最大番号+1。欠番は再利用しない）。
2. **本文は画面に沿って書く**: ユーザーは非エンジニア寄り。「どのURLを開く→どのボタンを押す→何を入力する→何をコピーする」の粒度で、専門用語には一言の説明を添える。
3. **秘密情報の受け渡しを明記する**: 取得したキー/URLをどこに設定するか（GitHub Secrets / Cloudflare Pagesの環境変数 / ローカル `.env`）を、**変数名つき**で書く。値そのものは手順書に書かせない（CLAUDE.md §3）。
4. **末尾に「完了確認」節を置く**: 設定が正しくできたかをユーザー自身が確認できるコマンド・URL・見えるはずの結果を書く。
5. **ユーザーに手順書のパスを案内し、完了報告を待ってから続行する**。先回りして次の実装を進めない。

## 判断基準・デフォルト値

- 1手順書=1サービス。複数サービスにまたがる作業は分割する。
- スクリーンショットは不要（外部UIはすぐ変わるため文字で書く）。UIが変わっていた場合に読み替えられるよう「〜という意味のボタン」と目的も併記する。
- 手順書にデザイン・ブランド固有の記述を持ち込まない（CLAUDE.md §4 デザインの局所性）。

## 例

- 良い例: 「⑤ 発行された『APIキー』をコピー → GitHubリポジトリの Settings → Secrets and variables → Actions → New repository secret で、Name に `YOUTUBE_API_KEY`、Secret に貼り付けて保存」
- 悪い例: 「APIキーを適切に設定してください」（どこに・どの変数名で・どう確認するかが無く、実行者の解釈で結果が変わる）

## 完了条件（すべて観測可能であること）

- [ ] `docs/setup/NN-名前.md` が存在する
- [ ] 必要な変数名と設定場所（Secrets / Pages env / .env）が本文に明記されている
- [ ] 末尾に「完了確認」節があり、確認コマンドまたは確認URLが書かれている
- [ ] ユーザーから完了報告を受けた（受けるまで後続作業は停止）
