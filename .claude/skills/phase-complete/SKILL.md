# フェーズ完了の定型フロー

CLAUDE.md §1（進め方）と §10（引き継ぎ・/clear）の具体化。フェーズ完了時に毎回同じ順で実行する。

出典: CLAUDE.md §1、code-review指摘修正の実績（commits 0910fe0、b4c4e61）。

## 手順

1. **ビルドとテストを通す**: `npm test` と `npm run build` を実行。どちらかが失敗している状態で完了報告をしない（CLAUDE.md §7）。
   - 既知の例外: ローカル `.env` に `YOUTUBE_API_KEY` が無い環境ではビルドが /videos で停止する。その場合はテスト全件パス＋CIのビルド成功をもって代える。
2. **ユーザー向けの動作確認手順を提示する**: 非エンジニアが実行できる形で、確認コマンドまたは開くURLと「見えるはずの結果」を書く。
3. **reviewer サブエージェントでレビューする**: `.claude/agents/reviewer.md` を使い、**フェーズ開始時点のコミットIDを基準として渡す**。指摘があれば修正し、修正分も再レビューする。
4. **`docs/progress.md` に引き継ぎを追記する**: 1〜10行で「何が完了・何が未着手・注意点」。次セッションが読んで作業を再開できる粒度。
5. **完了報告＋次フェーズの概要を出して停止する**: 承認なしに次フェーズへ進まない。あわせて `/clear` を案内する（前フェーズの作業ログを持ち越さない）。

## 判断基準・デフォルト値

- コミットはフェーズ内の意味単位で分ける。レビュー修正は「code-review 指摘修正」と分かるメッセージで別コミットにする（実績: 0910fe0、b4c4e61）。
- reviewer に渡す基準コミットが不明な場合は `git log` でフェーズ開始点を特定してから渡す。特定できない場合はその旨を報告に書く。

## 例

- 良い例: 「Phase 2 完了。確認: `npm run dev` → http://localhost:4321/videos で最新動画が表示されます。reviewer指摘2件（秘密情報・冪等性）は修正済み（コミット xxxx）。progress.md 更新済み。次は Phase 3（お仕事依頼ページ）です。承認をお願いします」→ 停止
- 悪い例: 「Phase 2 が終わったので、続けて Phase 3 のフォームも作っておきました」（承認前にフェーズをまたいでいる＝CLAUDE.md §1違反）

## 完了条件（すべて観測可能であること）

- [ ] `npm test` 全件パス（＋ビルド成功。ローカルキー無しの場合はCIビルド成功）
- [ ] ユーザー向け動作確認手順を提示済み
- [ ] reviewer の指摘がゼロ、または全件修正済み
- [ ] `docs/progress.md` に引き継ぎ追記済み
- [ ] 完了報告＋次フェーズ概要を出して**停止**した（次の実装に着手していない）
